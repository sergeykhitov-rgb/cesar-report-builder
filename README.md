# CESAR SATELLITE — конструктор отчётов и коммерческих предложений

Браузерная платформа для менеджера: данные клиента и объекта, оборудование, тариф, опции, акции и фотоматериалы заполняются в одной форме. Результат можно открыть по публичной ссылке, скачать как фирменное PDF и выгрузить как XLSX-смету.

## Запуск

Требуется Node.js 22.3 или новее.

```bash
npm ci
npm start
```

- редактор: <http://localhost:4600>
- тесты: `npm test`
- с телефона в той же сети: `http://<IP-компьютера>:4600`

## Что реализовано

- B2C и B2B, покупка и аренда;
- каталог из 155 уникальных позиций оборудования;
- автоматический расчёт оборудования, скидки, монтажа, абонентской платы и материальной ответственности;
- ручная корректировка цены позиции, монтажа, абонентской платы и ответственности;
- предупреждения для правил, которых нет в исходных справочниках: система не придумывает ставку;
- 14 акций, три приоритетные выбраны по умолчанию: «Два объекта выгоднее», «Приведи друга», «Выгодная предоплата»;
- отдельный PDF и XLSX для каждой системы оборудования; при нескольких системах скачивается ZIP;
- публичная клиентская ссылка без внутренних цен, источников и причин ручных корректировок;
- адаптивный интерфейс и публичный отчёт для компьютера и телефона.

## Каталоги и повторный импорт

Источники:

1. `Справочники_калькулятора_НДВ_00000002.xlsx` — тарифы, скидки, монтаж, ответственность, опции и правила аренды;
2. `Спецификация_НДВ_для кальк окт.xls` — основной каталог оборудования;
3. `Копия Спецификация_НДВ_6065286.xls` — контрольный вариант спецификации.

Импорт фиксирует SHA-256 и листы источников в `data/catalogs/import-manifest.json`. Команда:

```bash
python3 scripts/import-calculator-data.py \
  --calculator "/путь/Справочники_калькулятора_НДВ_00000002.xlsx" \
  --equipment "/путь/Спецификация_НДВ_для кальк окт.xls" \
  --equipment-copy "/путь/Копия Спецификация_НДВ_6065286.xls" \
  --output data/catalogs
node scripts/build-calculator-catalogs.js public/calculator-catalogs.js
```

Зависимости импортера закреплены в `requirements-calculator-import.txt`.

## API

- `POST /api/reports` — проверяет и атомарно сохраняет публичный snapshot;
- `GET /api/reports/:id` — получает отчёт;
- `GET /r/:id` — публичная страница;
- `POST /api/exports/pdf` — один PDF либо ZIP;
- `POST /api/exports/xlsx` — одна XLSX-смета либо ZIP.

Сервер сверяет коды с доверенным каталогом и проверяет арифметику в копейках. Лимит предложения — 200 позиций. Для PDF действует отдельный лимит тела 1 МБ и не более двух одновременных экспортов.

## Хранение ссылок

По умолчанию отчёты атомарно записываются в `REPORTS_DIR` или `data/reports`. Локально и на сервере с постоянным диском это долговечное хранение.

Важно: файловая система Render Free временная. Новые отчёты могут исчезнуть после перезапуска или деплоя. Версионированные файлы из `seed/` переживают деплой. Для действительно постоянных динамических ссылок подключите PostgreSQL/объектное хранилище или платный Render Persistent Disk — готовая схема и чек-лист приведены в `ИНСТРУКЦИЯ-ДЛЯ-ПРОГРАММИСТОВ.md`.

## Деплой и проверка

Render запускает Node-сервер, Netlify проксирует публичный домен. После деплоя проверьте:

1. загрузку редактора и каталога;
2. B2C, B2B и аренду;
3. публикацию и открытие `/r/:id` с телефона;
4. PDF/XLSX для одной системы и ZIP для смешанного комплекта;
5. отсутствие служебных полей в `GET /api/reports/:id`.

`npm audit --omit=dev` сообщает о двух moderate-записях в транзитивном `uuid` через `exceljs`. Уязвимый сценарий генерации UUID проектом не используется; `npm audit fix --force` предлагает несовместимое понижение ExcelJS и поэтому не применяется.
