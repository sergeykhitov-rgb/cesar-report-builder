# Инструкция для программистов: постоянное хранение CESAR SATELLITE

## 1. Текущее состояние

Приложение работает на Node.js 22.3+, без frontend-сборки. `server.js` отдаёт статику, проверяет расчёт, создаёт публичные ссылки и формирует PDF/XLSX. Отчёты сохраняются атомарно в `REPORTS_DIR` либо `data/reports`; встроенные постоянные примеры лежат в `seed/`.

Файловая система бесплатного Render временная. Динамический отчёт может исчезнуть при рестарте или новом деплое. Поэтому текущий бесплатный режим подходит для демонстрации, но не является постоянным хранилищем.

## 2. Рекомендуемая архитектура

- PostgreSQL хранит JSON отчёта и метаданные.
- S3-совместимое хранилище хранит фотографии; в JSON остаются URL.
- Публичный `id` остаётся случайным и неизменным.
- Приложение сначала пишет данные, затем возвращает ссылку.

```sql
CREATE TABLE reports (
  id TEXT PRIMARY KEY,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  data JSONB NOT NULL,
  schema_version INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX reports_created_at_idx ON reports (created_at);
```

Переменные окружения:

```text
DATABASE_URL=postgresql://...
S3_ENDPOINT=https://...
S3_BUCKET=cesar-reports
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_PUBLIC_BASE_URL=https://...
```

Допустимые варианты: Neon/Supabase/PostgreSQL для JSON; Cloudflare R2, Supabase Storage, Selectel или AWS S3 для фото. Альтернатива без БД — платный Render Persistent Disk и `REPORTS_DIR=/var/data/reports`.

## 3. Точки замены в коде

В `server.js` замените файловые операции создания и чтения адаптером:

```js
await reports.create(id, publicSnapshot);
const report = await reports.get(id);
```

Сохраните текущие свойства:

- серверный allowlist публичных полей;
- проверка оборудования по `data/catalogs/equipment.json`;
- проверка строк, количества, скидки и итогов в копейках;
- максимум 200 позиций;
- ответ `409`/повтор генерации ID при коллизии;
- отсутствие перезаписи существующего ID.

Для фотографий замените `fileToDataURL` в `public/editor.js` на прямую загрузку в бакет по подписанному URL. Не передавайте секрет S3 в браузер.

## 4. Миграция

1. Создать БД и таблицу `reports`.
2. Создать приватный бакет и правила чтения публичных объектов отчёта.
3. Добавить env-переменные в Render, не в Git.
4. Реализовать storage adapter и тесты create/get/collision/not-found.
5. Импортировать существующие `data/reports/*.json` и `seed/*.json` идемпотентным скриптом.
6. Для base64-фото загрузить бинарные данные в бакет и заменить их URL.
7. Сверить количество и SHA-256 записей до/после миграции.
8. Сделать backup/restore rehearsal.
9. Переключить чтение на БД, затем запись; оставить файловый fallback только на время миграции.

## 5. Каталоги и расчёт

Импорт выполняется `scripts/import-calculator-data.py`; происхождение файлов и SHA-256 фиксируются в `data/catalogs/import-manifest.json`. Основная спецификация имеет приоритет, контрольная копия используется для проверки конфликтов. После импорта запускается `node scripts/build-calculator-catalogs.js public/calculator-catalogs.js`.

Ручные overrides допустимы для цены позиции, монтажа, абонентской платы и материальной ответственности. Если исходный Excel не задаёт правило, калькулятор обязан показать предупреждение, а не придумывать цену. Приоритет акции хранится в справочнике; три акции с наивысшим приоритетом выбраны по умолчанию, но менеджер может их отключить.

## 6. Экспорты

- `POST /api/exports/pdf`: один PDF на одну систему, ZIP при нескольких.
- `POST /api/exports/xlsx`: одна смета на одну систему, ZIP при нескольких.
- PDF использует локальный Onest, XLSX содержит только клиентские данные.
- Служебные `source`, `overrideReason`, raw catalogs и внутренние предупреждения не экспортируются.

PDF endpoint принимает не более 1 МБ и обслуживает не более двух генераций одновременно. Не удаляйте эти ограничения без нагрузочного теста.

## 7. Проверка релиза

```bash
npm ci
npm test
node --check server.js
node --check public/calculator-engine.js
node --check public/calculator.js
node --check public/editor.js
git diff --check
```

На production URL проверьте B2C, B2B, аренду, ручной ноль, смешанные системы, три приоритетные акции, публичную ссылку, мобильный вид, PDF, XLSX и ZIP. Перезапустите сервис и убедитесь, что отчёт сохранился — это обязательный приёмочный тест постоянного хранилища.

## 8. Безопасность и эксплуатация

- Закрыть редактор и POST-методы авторизацией; `/r/:id` оставить доступным по ссылке.
- Добавить rate limit, журнал действий, срок хранения и удаление по требованиям бизнеса.
- Делать резервные копии БД и настроить lifecycle для файлов.
- Не применять `npm audit fix --force`: текущие две moderate-записи относятся к транзитивному `uuid` в ExcelJS, а автоматический fix предлагает несовместимое понижение. Пересматривать зависимость при обновлении ExcelJS.
